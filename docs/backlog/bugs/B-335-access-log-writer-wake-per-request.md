# B-335: アクセスログのスレッドを要求ごとに起こす

**状態: 修正済み（feat/v0120-perf、2026-11-07）**

## 事象

アクセスログが有効（ライブラリの既定）だと要求ごとに `futex` が 2 本走る（strace、4680 要求で 9572）。送り手は `SyncSender::try_send` の中で
受け手を `notify` し、受け手は `recv_timeout` でまた眠る。ワーカーのホットパスに futex が入り、ログのスレッドが CPU を取り合う。

## 調査メモ

`access_log.rs` の `spawn_log_thread` は `rx.recv_timeout(flush_interval)` で 1 件ずつ受ける。

## 改修案

受け手は「まとめて読む」: キューを空にしたら短い時間（1 ms）眠ってからまた読む。キューが空のまま一定時間続いたときだけ
`recv_timeout` で待つ（アイドルのときの無駄な起床を避ける）。負荷のあるときは受け手が眠っていない（park していない）ので、
送り手の `notify` は futex を呼ばない。

## 受け入れ条件

- 負荷中の futex が要求数に比例しなくなる。ログが欠けない（既定のチャネルの容量の範囲）。終了時に全部書き出す。
