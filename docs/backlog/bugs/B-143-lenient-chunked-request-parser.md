# B-143: chunked の要求の本文を緩く解析していた（上流と本文の境界の解釈がずれる）

**状態: 完了（feat/v080-release、2026-10-18。F-236 の再走査の F5）**

## 症状

`ChunkedDecoder` は、サイズ行の 16 進でない文字・裸の LF を読み飛ばし、桁あふれを飽和させ、チャンクの後ろの CRLF が無くても
状態を戻して続けていた。veil は本文の終端を決めるためだけに解析し、生のバイトを上流へ送るので、上流の解析と違えば要求の境界が
ずれ、後ろのバイトが上流で別の要求になり得た。

## 修正

要求の本文用に厳格なモード（`ChunkedDecoder::new_request`）を足した。RFC 9112 §7.1 に合わないもの（16 進でない文字・
桁あふれ・空のサイズ・裸の LF・チャンクの後ろの CRLF の欠け・拡張やトレーラーの LF/NUL・BWS の後の桁）は `Invalid` にし、
HTTP/1.1 の前段では 400、転送中は打ち切る。応答（上流から）は従来どおり緩く読む（上流の互換のため）。

## 試験

`http_utils::tests::strict_request_decoder_rejects_lenient_framing_and_reports_end`。
