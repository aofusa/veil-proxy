# B-139: ルートのキャッシュのキーが固定シードの 64 ビットのハッシュで、衝突を作ると別のルートへ入れた

**状態: 完了（feat/v080-release、2026-10-17。F-236 の監査の F6）**

## 症状

スレッドごとのルートの LRU は、(ホスト, パス, メソッド, IP) の xxh3 の 64 ビットだけをキーにし、元のキーを比べない。
シードは公開の定数（`0xdead_beef_cafe_0000`）なので、手元で 2^32 程度の試行で衝突するパスの組を作れる。
保護の無い包括のルート（`/*`）で 1 つ目をキャッシュさせてから、保護のあるルート（`/admin/*` の JWT・IP 制限）に入るはずの
2 つ目を送ると、キャッシュから包括のルートが選ばれ、保護を回避できた。

## 修正

シードをプロセスごとの乱数にした（`routing::route_key_seed`。最初の参照で 1 回だけ作る `OnceLock`）。シードを知らなければ
衝突を狙って作れない。ホットパスの増分はアトミックの読み 1 つ。

## 試験

`routing` の既存の単体テスト（キーの一致・不一致）。
