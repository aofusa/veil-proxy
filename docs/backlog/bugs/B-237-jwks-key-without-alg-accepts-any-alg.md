# B-237: JWKS の鍵に `alg` が無いと、トークン側の `alg` でその鍵種の任意のアルゴリズムを受理する

**状態: 未修正（2026-10-27 起票。セキュリティレビュー XT-02）**

## 出典

2026-10-27 のセキュリティレビュー（v0.9.2 の `src/jwt_verify.rs` L159 付近の読解）。

## 事象

- JWKS の鍵（`kty: RSA`/`EC`）に `alg` が無いと、トークンの `alg` がその鍵種で検証可能な任意のアルゴリズム（RS256/384/512・PS256/384/512）で受理される。
- HMAC 系は実装していないので `alg` の混同（HS256 + 公開鍵）は不可能、`none` も拒否される。鍵種の混同も無いので実害は小さいが、
  発行者が RS256 だけを使う前提で PS256 の署名を受けるのは意図と違う。

## 改修案

- 鍵ごとに `alg` を必須にする（無い JWKS は設定の検証で警告）か、ルートの `[route.security.jwt] allowed_algs`（既定は鍵種から導く）で
  受けるアルゴリズムを固定できるようにする。設定キーを足すので `examples/config.toml`・`docs/guide/`（英・日）を同じ変更で更新する。

## 受け入れ条件

- 単体: `alg` 無しの鍵と `allowed_algs = ["RS256"]` で PS256 のトークンが拒否される。
