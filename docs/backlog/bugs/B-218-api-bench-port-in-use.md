# B-218: API ベンチが、ポート 3000 を使っている別のサーバを測っていた

**状態: 修正済み（v0.10.0）**

## 出典

v0.10.0 の API ベンチ（`tools/api-bench/run_bench.py`、2026-10-27）。axum + tokio を含む全対象が 12.6〜12.9k req/s・p99 16〜19ms で
並び（v0.9 の記録は 6 万台）、他の負荷を止めて回し直しても同じだった。

## 事象と原因

- 待ち受けが `127.0.0.1:3000` 固定で、ホストの Grafana のコンテナ（`docker-proxy` が `127.0.0.1:3000`）が同じポートを使っていた。
- 対象のサーバは bind に失敗してすぐ終わるが、`wait_port` はポートに繋がるかだけを見るので、Grafana に繋がって「起動した」と判定し、
  wrk は Grafana（docker-proxy 経由）を測っていた。`cpu_pct` が全行 0 だったのがその印。
- `allocs.py` も同じポート固定。

## 修正

- 待ち受けを `BENCH_PORT`（既定 3000）にし、`run_bench.py`・`allocs.py`・veil の Python の対象（`BENCH_LISTEN`）へ渡す。
- 対象を起動する前にポートが応えたら止める。起動待ちの間にサーバのプロセスが終わったら「起動失敗」にする（別のプロセスの応答と
  取り違えない）。`allocs.py` も起動直後に終わっていたら止める。
- `tools/api-bench/README.md` に書いた。
