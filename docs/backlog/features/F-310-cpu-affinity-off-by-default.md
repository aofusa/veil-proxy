# F-310: ワーカーを既定で CPU に固定しない（`[performance] cpu_affinity`）

**状態: 完了（feat/beat-nginx、2026-11-14）**

## 背景

veil は起動時に、すべてのリスナー（HTTP の TCP・HTTP/3・L4）のワーカー *i* を、プロセスが使える *i* 番目の CPU に
必ず固定していた（`core_affinity::set_for_current`）。設定で外す方法は無かった。

F-309 の後も HTTP/3 の 1 接続 1 ストリーム（h2load-h3 `-m1`）で nginx に届かなかった（lab48: 静的配信 −11%・中継 −7%）。
nginx は既定でワーカーを固定しない（`worker_cpu_affinity` は既定で無効）。固定の有無だけを変えた同じバイナリ
（計測用の一時的なビルドで、環境変数で固定を外す）を nginx と交互に測ると、負荷ツール・上流と CPU を分け合う標準の
配置では、固定しない方が HTTP/2・HTTP/3 で明らかに速かった。

- 固定したワーカーは、パケットを受けた CPU（ループバック・veth では送り手の CPU）へスケジューラが寄せられない
  （wake affine が効かない）。負荷ツールや上流と同じ CPU に当たっても動けない。
- 同じ機械の複数の veil（Istio・Linkerd のサイドカー、`--cpus` で絞ったコンテナ）は、どれも自分が使える CPU の
  集合が機械の全部なので、全部が先頭のコア（0, 1, ...）に固定される。

## 計測

### 標準の配置（lab49、aofish のコンテナ間、CPU を負荷ツール・上流と分け合う。3 ラウンドの中央値、rps）

| 構成 | nginx | 固定（従来） | 固定しない | 固定しない / 固定 |
|---|---:|---:|---:|---:|
| HTTP/3 `-m1` 静的配信（`h2_1_feat_http3`） | 33,473 | 30,759 | **34,226** | +11% |
| HTTP/3 `-m1` 中継（`h3_proxy`） | 26,039 | 23,715 | **26,774** | +13% |
| HTTP/3 `-m10` 静的配信 | 41,419 | 41,338 | **43,593** | +5% |
| HTTP/3 `-m10` 中継 | 31,364 | 33,864 | **37,158** | +10% |
| HTTP/1.1 静的配信（`h2_1_ktls_0_lb_kernel_ofc_1`、wrk） | 50,557 | 79,018 | 79,125 | 0% |
| HTTP/1.1 中継（`h2_1_feat_proxy`） | 30,025 | **45,961** | 43,297 | −6% |
| HTTP/2 静的配信（h2load） | 38,674 | 55,987 | **62,959** | +12% |
| HTTP/2 中継 | 25,354 | 46,632 | **51,048** | +9% |

- HTTP/1.1 の p99 は固定しない方が低い（静的配信 2.33〜2.35ms 対 3.04〜3.63ms、中継 7.2〜8.1ms 対 11.1〜15.6ms）。
- HTTP/1.1 の中継の −6% は 3 ラウンドのうち 2 ラウンドで、そのラウンドだけコンテキストスイッチが 0.22 → 0.56/要求に
  増えた（上流の nginx・wrk と同じ CPU に寄った回）。
- 固定しないと、HTTP/3 の `-m1` でも nginx を上回る（静的配信 +2%・中継 +3%）。

### 専有の配置（lab50、サーバは CPU 0-7、負荷ツールと上流は 8-15。3 ラウンドの中央値、rps）

| 構成 | nginx | 固定（従来） | 固定しない | 固定しない / 固定 |
|---|---:|---:|---:|---:|
| HTTP/3 `-m1` 静的配信 | 43,258 | 40,175 | 41,168 | +2% |
| HTTP/3 `-m1` 中継 | 31,286 | 29,181 | 27,970 | −4% |
| HTTP/3 `-m10` 静的配信 | 44,554 | 47,905 | 47,712 | 0% |
| HTTP/3 `-m10` 中継 | 34,198 | 38,267 | 38,886 | +2% |
| HTTP/1.1 静的配信 | 55,778 | 77,561 | 79,273 | +2% |
| HTTP/1.1 中継 | 36,016 | 44,560 | 47,237 | +6% |
| HTTP/2 静的配信 | 38,742 | 68,665 | 72,277 | +5% |
| HTTP/2 中継 | 25,343 | 50,578 | 49,014 | −3% |

- 差は ±6% 以内で、どちらが速いかもそろわない（ラウンドごとの揺れの方が大きい。HTTP/1.1 の中継の固定は 34,053〜47,637）。
- HTTP/3 の `-m1` は、どちらの配置でも負荷側（h2load-h3 の 4 スレッド）が律速。負荷側の 1 要求あたりの CPU は veil が相手の
  ときの方が多い（静的配信 nginx 91.6µs・veil 98.0µs、中継 121.0µs・130〜133µs）ので、専有の配置では nginx を下回る
  （静的配信 −5%・中継 −11%）。サーバの 1 要求あたりの CPU は静的配信で同じ（160.8µs・162.7µs）。

## 対応

- `[performance] cpu_affinity` を足す。`"off"`（既定）は固定しない、`"cores"` は従来どおりワーカー *i* をプロセスが
  使える *i* 番目の CPU に固定する（`isolcpus` で隔離したコア等、CPU を専有させる場合。固定しないスレッドは隔離した
  コアに置かれない）。HTTP の TCP・HTTP/3・L4 のワーカーすべてに効く。
- 固定する CPU の一覧は `listener_workers::worker_core_ids` で決め、起動時に方針を 1 行記録する（`log_cpu_affinity`）。
  ホットパスには何も足さない。
- 利用者ガイド（`configuration.md`・`performance.md`・`migration-nginx.md`・`features.md` の英日）と
  `examples/config.toml`、AGENTS.md（リスナー・ワーカー）に書いた。
