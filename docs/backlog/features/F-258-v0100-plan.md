# F-258: v0.10.0 の機能改修とベンチマークの提出（親チケット・全体設計）

**状態: 未着手（2026-10-25 起票・設計。作業ブランチ `feat/v0100-system-ca-multilisten-api-tickets` はチケットと設計だけ）**

## 依頼の要約

1. veil 本体: 上流の `tls_ca` に OS の CA 証明書を使う指定（配布物の既定は OS の CA、コンテナは組み込みの CA のまま）／複数ポートでの待ち受け。
2. ライブラリ利用時だけの機能（**veil 単体・本体のプロキシ・Web サーバには一切影響を出さない**）: WebSocket・HTTP/1.1 の
   プロトコルアップグレード・Swagger UI の完全オフライン化・gRPC のルートの OpenAPI 掲載・multipart/form-data（ファイルのアップロード）・
   Rust と Python のヘルパー（Cookie・リダイレクト・静的配信・CORS・認証認可・GraphQL・gRPC（クライアント含む）・動的 DI・
   バックグラウンドタスク）・FastAPI の生態系の利用。
3. 改修後、HttpArena に veil 単体・Rust API・Python を、the benchmarker に Python を提出する。

### 決定事項（2026-10-25、利用者の確認済み）

- 版は **v0.10.0**。パッケージ名は Rust `veil-proxy-kit`（ライブラリ名 `veil_kit`）・PyPI `veil-api-kit`（`import veil_kit`）。
- Python の `async def` の既定の実行先を常駐のループにする（旧来は `async_mode="pool"`）。
- `[[listener]]` の `secure_redirect` の既定は `false`。
- WebSocket のルートは OpenAPI に載せる（Rust・C・Python。F-262 の 1.1・F-263）。
- **タグの作成・push・GitHub Release の公開・各レジストリへの公開は許可済み**（F-276）。ベンチマークの提出（fork・push・PR・コメント）は
  各手順の前に確認を取る（F-269）。
- ベンチマークの提出の作業は veil のリポジトリに影響を出さない（`docs/artifacts/benchmark/` の下だけ。F-269）。

- 1 チケット 1 PR（AGENTS.md「1 タスク = 小粒度」）。段階 1 と段階 2 は独立なので並行できる。
- v0.10.0 にするのは、`[[listener]]`・`[tls_client]`・ライブラリの大きな追加と、Python の `async def` の既定の実行先の変更（F-263）があるため。
  リリースノート（`docs/releases/v0.10.0.md`）に既定の設定（新規インストール）の変化と互換の注意を集める。

## 全チケットに共通の設計の原則

1. **本体への影響ゼロ（ライブラリの機能）**: F-261〜F-268 の本体側の変更は `cfg(feature = "handler")` の分岐だけ。
   `tests/api/library_e2e.sh nonregression` の検査に新しい記号（`veil::api::upgrade`・`veil::api::ws`・`veil::api::client`・
   `veil::api::multipart`・`veil_kit::`）と同梱資産の文字列（`swagger-ui`）を足し、`full`・`full-container` のバイナリに無いことを確かめる。
   プロキシの性能は「バイナリが同じ」ことで担保し、念のため `tools/perf` の suite_ab を段階 3 の終わりに 1 回回す。
2. **ホットパス規則**: 本体の F-259・F-260 は接続・要求ごとの経路に確保・ロック・ログを足さない（解決は設定ロード時、要求ごとは
   `Arc` の参照と配列の添字だけ）。ライブラリの機能も同じ規則（WebSocket のフレームはプールのバッファでその場でマスクを外す、
   multipart は `Bytes` の切り出し、DI の解決は登録時）。
3. **依存**: 本体に足すのは `rustls-native-certs`（F-259、小さい）だけ。async-graphql・prost・JWT・strawberry・grpcio 等は
   ヘルパー（`veil_kit` の feature・`veil-api-kit` の extras）の中に閉じる（F-207 の方針の継続）。
4. **全 OS**: 本体の変更（F-259・F-260）は Linux（io_uring・epoll）・FreeBSD・OpenBSD・NetBSD・macOS・Windows のサンドボックス込みで確かめる
   （`tools/qemu/`・ssh の実機）。ライブラリの機能は Linux の両バックエンドを必須、他 OS は F-203 の手順で 1 回。
5. **文書**: 外部契約（設定キー・API）を変えたら同じ PR で `docs/guide/`（英日）・`crates/veil-python/docs/`（英日）・`examples/config.toml`。
