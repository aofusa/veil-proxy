# F-226: TOML のルートの要求のタイムアウト・条件付きリトライ・ミラー・フォルトの遅延

**状態: 未着手（2026-10-16 起票。F-219 の TOML 側の残り）**

## 目的

F-219 はメッシュのデータプレーンにルート単位の要求のタイムアウト・条件付きのリトライ・ミラー・フォルトの遅延を実装し、
メッシュ無しの TOML のルートには固定応答・重み付き分割・フォルトの中断・CORS のプリフライトだけを出した
（`[route.traffic]`。ルート照合の直後に Backend を選ぶだけで済むもの）。残りの 4 つを TOML のルートにも出す。

## 設計の要点

- 4 つとも上流への送受信の途中に入る（ルート照合の層では済まない）。既存のプロキシの全経路（HTTP/1.1 の TLS / 平文、
  HTTP/2 のバッファ・ストリーミング、HTTP/3 のバッファ・ストリーミング、WebSocket）に入れる必要がある。
- 設定の無いルートは分岐 1 個で、既存の経路のコストを増やさない（ルートに解決済みの `Arc` を持たせる。F-159 と同じ）。
- リトライは本文を再送できる要求だけ（F-177 と同じく要求バッファのプールから複製）。ミラーは応答を待たず、同時実行数に上限。
- フォルトの遅延は `runtime::time` のタイマーで（スレッドを止めない）。

## 受け入れ条件

- 既存のプロキシの性能が退行しない（`tools/perf/suite_ab.sh` の main との交互 A/B、比の中央値 0.98 以上・0.95 未満なし）。
- 各プロトコルの E2E（`tests/standalone_e2e.rs`）、`docs/guide/routing.md`（英日）・`examples/config.toml`。
