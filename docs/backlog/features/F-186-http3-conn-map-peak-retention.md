# F-186: HTTP/3 の接続表がピーク時の容量を保持し続ける

**状態: 未着手**

## 背景（F-185 のリーク試験で判明）

`http3_server` の接続表 `HashMap<ConnectionId, Http3Handler>` は 1 エントリに数 KB の `Http3Handler` を値で持つ。
同時接続数のピーク（アイドルタイムアウト前の接続を含む）に合わせて表の容量が倍増し、HTTP/3 の 1 接続 1 要求の
チャーン（1 サイクル 300 接続）では 1 → 2 → 4 → 8 → 16MB（ワーカーあたり）まで伸びた。hashbrown は縮まないので、
接続が減ってもこの大きさのまま残る。上限はある（ピークの同時接続数で頭打ち）のでリークではない。

## 案

1. `Http3Handler` を `Box` にして表のエントリを小さくする（表は 1 エントリ数十バイトになる）。接続ごとに 1 回の
   確保が増えるので、HTTP/3 の交互 A/B（`tools/perf/h3_ab.sh`）で確認する。
2. ワーカーのアイドル点（`alloc_tune::idle_tick` を呼ぶ HTTP/3 のタイムアウト）で、`len` が容量の 4 分の 1 を下回って
   いたら `shrink_to` する（要求ごとの経路では縮めない）。

確認は `tools/perf/leak_check.sh` の `h3_churn` の生存バイトと、負荷後の RSS。
