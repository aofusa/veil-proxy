# veil v0.11.0

veil 0.11.0 adds WebSocket over HTTP/2 and HTTP/3, precompressed static files, a C kit for the API library and a
failure policy for Proxy-Wasm filters, which now fail closed by default. It also fixes the issues found by a
security review of the whole code base before this release. Read the upgrade notes: some of the fixes reject
configurations or requests that 0.10 accepted.

## Install

| | |
|---|---|

| RHEL-compatible, Fedora, Amazon Linux | signed dnf repository, `dnf install veil`, `systemctl enable --now veil` |
| Homebrew (macOS, Linux) | `brew install aofusa/tap/veil`, `brew trust aofusa/tap` (Homebrew 7 and later), `brew services start veil` |
| Windows | MSI and zip (x64 and arm64) on this page; `winget install Aofusa.Veil` |
| FreeBSD, OpenBSD, NetBSD | ports for each tree (`veil-0.11.0-bsd-ports.tar.gz`, [packaging/bsd/ports](https://github.com/aofusa/veil-proxy/blob/main/packaging/bsd/ports/README.md)) |

| Container | `ghcr.io/aofusa/veil` and `docker.io/aofusa/veil` (same digests and signatures): `latest` = `v0.11.0` = `musl-v0.11.0`, and `glibc-v0.11.0` |

## New

- **WebSocket over HTTP/2 and HTTP/3** (RFC 8441, RFC 9220). Set `enable_connect_protocol = true` in `[http2]` or
  `[http3]`. veil then accepts extended CONNECT requests (`:protocol = websocket`), routes them like a GET and relays
  them to the upstream as an HTTP/1.1 upgrade. API library handlers receive them too. See
  [Protocols](https://github.com/aofusa/veil-proxy/blob/main/docs/guide/protocols.md).
- **Precompressed static files.** `precompressed = ["br", "gzip"]` in a file route's `[route.action]` serves `app.js.br`,
  `app.js.gz` or `app.js.zst` next to `app.js` when the client accepts that encoding. Like nginx's `gzip_static`, it
  still uses `sendfile` and kTLS, works without `[route.compression]`, skips a sibling that is older than the original
  file and adds `Vary: Accept-Encoding`.
- **Proxy-Wasm failure policy.** `failure_policy` in `[wasm.defaults]`, overridable per module, decides what happens
  when a filter traps, runs out of fuel or time, cannot be instantiated, fails its start-up callbacks or pauses a
  request that cannot wait:
  - `"fail_closed"` (default) answers 503
  - `"fail_open"` skips the module
  - `"fail_reload"` answers 503 and replaces the instance

  Failures are counted in `veil_wasm_failures_total{filter, phase, reason, action}`. A paused request now waits for
  the filter on every protocol and in the mesh, so an external authorization result applies to the request. A local
  response sent from the response-headers phase is used.
- **C kit** (`libveil_kit`, `veil_kit.h`): cookies (signed, encrypted, with key rotation), sessions, Basic, Bearer,
  API key and JWT authentication (verification, issuing, JWKS), dependency injection, background tasks, GraphQL,
  gRPC, an HTTP client with retries, safe redirects and test helpers. It reuses the Rust kit, so cookie and token formats are the same in all three languages. The core C
  API gains middleware, per-request values, after-send hooks and lifecycle hooks. CMake packages `veil::veil` and
  `veil::kit` are included.
- **kTLS HTTP/1.1** sends file bodies and relays proxy bodies through the same zero-copy paths as plaintext HTTP/1.1
  (`sendfile(2)` with a time limit and yielding, in-place non-blocking `splice(2)`).
- The Windows `veil.exe` carries the veil icon and version information, and the MSI shows it in the list of
  installed apps.

## Security

Fixed after a review of the whole code base (tickets B-313 to B-325):

- **kTLS with TLS 1.2 (AES-GCM, Linux):** the first record that the kernel sent reused the nonce of rustls's
  Finished message, which exposes the GCM authentication key. The explicit nonce now starts from a random value.
  TLS 1.3 was not affected. If you use kTLS with TLS 1.2 clients, upgrade.
- **Request handling:**
  - HTTP/2 and HTTP/3 handler streaming paths and extended CONNECT now go through `[route.security]` and Proxy-Wasm.
  - HTTP/1.1 counts leading empty lines against the header size limit.
  - HTTP/1.1 rejects CONNECT authority-form targets on normal routes and malformed `Content-Length` values.
  - Header values with CR or LF from HTTP/2 upstreams, handlers and Proxy-Wasm are never written to HTTP/1.1.
- **Response cache:**
  - `no-cache` (also in a second `Cache-Control` line, `Pragma` or an expired `Expires`) is honoured.
  - Responses to requests carrying cookies are stored only when the upstream marks them shareable (`public`,
    `s-maxage`).
  - Cache keys include the route, and `Vary` values are length-prefixed so they cannot be forged.
  - The static file cache keeps nested routes' containment.
  - HTTP/2 and HTTP/3 whole-file reads have a memory budget (503 when exceeded).
- **Proxy-Wasm:**
  - A pause that is never resumed no longer lets the request through.
  - `proxy_set_buffer_bytes` is bounds-checked, and a zero-size allocation fails.
  - `http_call` and gRPC call IDs are unique across requests.
  - L4 filters follow the failure policy and hold paused data instead of forwarding it.
- **Authentication and routing:**
  - JWT `exp` and `nbf` accept fractional NumericDate values and reject non-numeric ones.
  - IP lists are validated, and an allow list with no valid entry denies everything.
  - `$path` in redirects always starts with `/` (no open redirect through `//host`).
  - A client can no longer bypass path rewriting by sending `content-type: application/grpc`.
- **Transport:**
  - h2c is chosen per upstream server, so `https://` servers in a mixed group are never sent plaintext.
  - Background cache revalidation (stale-while-revalidate) is skipped for `https://` upstreams and for requests
    with credentials, instead of being sent in plaintext with the client's cookies.
  - OTLP `https://` endpoints are rejected instead of being sent in plaintext.
  - HPACK never-indexes `authorization`, `cookie` and their proxy and response counterparts on upstream HTTP/2.
- **Mesh:**
  - JWT prefix handling no longer panics on multi-byte characters, and `from_cookies` is honoured.
  - Absolute-form HTTP/1.1 targets are authorized by path, and ambiguous body framing is rejected.
  - Every network RBAC filter in a chain applies, so Istio TCP `DENY` is enforced alongside `ALLOW`.
  - `x-forwarded-client-cert` from clients without a certificate is dropped.
  - Upstream TLS without SAN matchers checks the SNI name.
  - Revocation lists (`crl`) are rejected instead of being ignored.
  - Linkerd inbound connections use the default policy when the port policy has not arrived.
- **API library:**
  - The HTTP client keeps `http://` and `https://` connections in separate pools.
  - Errors converted into responses no longer include URLs or internal addresses.
  - `http://unix/` is no longer treated as a Unix socket.
- **ACME on Windows:** keys and the storage directory get a DACL that allows only SYSTEM, Administrators and the
  owner (the equivalent of mode 0600/0700).

## Fixes

- **HTTP/1.1 zero-copy proxying:**
  - A `splice(2)` relay that failed in the middle of a request body no longer resends the request head on the same
    upstream connection.
  - The epoll backend no longer spins on `EAGAIN` in `splice`.
  - Response heads, chunked bodies and upstream writes on the splice path have time limits.
- **`buffering = "adaptive"`** decides by the response length, as documented, instead of buffering every GET.
- **Compression:**
  - `Accept-Encoding` honours `q=0` and `preferred_encodings`.
  - The default configuration compresses SVG.
  - Builds without the `compression` feature no longer send uncompressed bodies labelled as compressed.
  - 304 responses for compressed files carry the weak `ETag`, and the compressed-file cache notices replaced files.
- **HTTP/1.1 file routes** open files relative to the matched route's own root (nested routes could serve another
  route's files through relative links).
- **WebSocket:**
  - On io_uring, the relay no longer drops data that was already received.
  - The relay waits on both directions instead of polling. In our benchmark, WebSocket throughput is about three times
    that of 0.10.1.
  - On macOS and the BSDs (kqueue), the relay no longer stalls in one direction.
  - Non-101 upstream answers are passed on in full.
  - Upgrades go through response header rules, CORS and Proxy-Wasm.
- **Windows:**
  - HTTP/3 to TLS upstreams no longer crashes the process.
  - UDP ignores ICMP port-unreachable reports (`SIO_UDP_CONNRESET`).
  - The E2E suite runs on Windows.
- **macOS** no longer logs a warning per worker at start-up because CPU pinning is unsupported there.
- **`mesh-linkerd` builds again** (broken in 0.10.1; release builds were not affected).

## Performance

Measured against 0.10.1 with alternating runs of the full suite (133 configurations, Linux x86_64): median ratio
0.993, and 1.013 after rerunning the 15 configurations below 0.95 with more iterations. On FreeBSD aarch64, all
scenarios are within 2–4 % (VM noise). Details and the comparison with nginx are in
[docs/perf](https://github.com/aofusa/veil-proxy/blob/main/docs/perf/README.md).

## Upgrade notes

- **Proxy-Wasm filters now fail closed.** A filter that traps or exceeds its limits answers 503 instead of letting
  the request through. To keep the 0.10 behaviour, set `failure_policy = "fail_open"` in `[wasm.defaults]` or on
  the module.
- **IP lists are validated when the configuration loads.** An invalid entry in `allowed_ips`, `denied_ips`,
  `trusted_proxies` or `[security] blocked_ips` stops start-up or rejects the reload. Before, it was skipped
  silently, and an allow list with no valid entry allowed everyone.
- **OTLP over `https://`** is rejected at load time. veil's exporter sends plaintext only. Point it at a local
  collector over `http://`.
- **Response cache:** entries are keyed by route, so the first requests after the upgrade are misses. Responses
  that are not shareable (above) are no longer cached.
- **`target_path_prefix` now applies to gRPC requests too.** To pass gRPC paths through unchanged, leave
  `target_path_prefix` empty.
- **WebSocket polling settings** (`websocket_poll_mode`, `websocket_poll_timeout_ms`, `websocket_poll_max_timeout_ms`,
  `websocket_poll_backoff_multiplier`) are ignored. They are still accepted.
- **A backend host named `unix`** (`http://unix/...`) is rejected. Use `http://unix:/path.sock` for Unix sockets.
- **Mesh:**
  - xDS configurations with a `crl`, or with SAN matchers but no `trusted_ca`, are rejected (NACK).
  - Upstream TLS without SAN matchers now checks the certificate against the SNI name.
- **API library:** `Response::from(ClientError)` returns `Bad Gateway` / `Gateway Timeout` without details. Log the
  error itself for the details.

## Known limitations

- Prebuilt BSD binaries are x86_64 only (aarch64 BSD: build from the ports or from source).
- macOS binaries are not signed with a Developer ID or notarized. Homebrew and `cargo binstall` installs are not
  affected by Gatekeeper; an archive downloaded with a browser may need `xattr -d com.apple.quarantine veil`.
- WebSocket over HTTP/2 and HTTP/3 is relayed to upstreams over HTTP/1.1 (extended CONNECT to an HTTP/2 upstream is
  not used), and the number of tunnels per connection is limited only by the stream limits.
- Mesh: certificate revocation lists are not checked, and Envoy's `auto_sni` (SNI taken from the request's Host) is
  not implemented.
