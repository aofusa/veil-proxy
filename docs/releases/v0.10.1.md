# veil v0.10.1

veil 0.10.1 makes the same configuration behave the same on HTTP/1.1, HTTP/2 (TLS and h2c) and HTTP/3. In 0.10.0,
several features (HEAD responses, response header rules, Proxy-Wasm response phases, compression, the circuit
breaker, request-body timeouts and some metrics) worked on some protocols or paths and not on others. These are the
changes since 0.10.0.

## Install

| | |
|---|---|
| Debian, Ubuntu | signed apt repository, `apt install veil` (the service starts) |
| RHEL-compatible, Fedora, Amazon Linux | signed dnf repository, `dnf install veil`, `systemctl enable --now veil` |
| Homebrew (macOS, Linux) | `brew install aofusa/tap/veil`, `brew services start veil` |
| Windows | MSI and zip (x64 and arm64) on this page; `winget install Aofusa.Veil` |
| FreeBSD, OpenBSD, NetBSD | ports for each tree (`veil-0.10.1-bsd-ports.tar.gz`, [packaging/bsd/ports](https://github.com/aofusa/veil-proxy/blob/main/packaging/bsd/ports/README.md)) |
| Rust | `cargo binstall veil-proxy` (prebuilt, minisign-verified) or `cargo install veil-proxy --locked --features full` |
| Container | `ghcr.io/aofusa/veil` and `docker.io/aofusa/veil` (same digests and signatures) |
| Kubernetes | `helm install veil oci://ghcr.io/aofusa/charts/veil --version 0.10.1` |
| API library | Rust `veil-proxy` + `veil-proxy-kit` on crates.io; Python `veil-api` + `veil-api-kit` on PyPI; C headers and libraries in the release assets |

## Static files

- **HEAD** responses to files, `Respond` routes and error responses no longer carry a body. Before, HTTP/1.1
  keep-alive connections got out of step (the next response was read as part of the body) and HTTP/2 clients saw a
  PROTOCOL_ERROR.
- **Range requests** (206, 416 with `Content-Range: bytes */<size>`, `Accept-Ranges: bytes`) work on HTTP/2 and
  HTTP/3, and for `mode = "memory"`, not only on HTTP/1.1 file routes.
- **`ETag` and `Last-Modified`** are sent for files, with `304 Not Modified` for `If-None-Match` and
  `If-Modified-Since`, and `If-Range` support. Compressed responses use a weak `ETag`.
- **Compression** (`[route.compression]`) applies to HTTP/1.1 file responses too. Responses that are not compressed
  still go out with `sendfile`. Files larger than 8 MiB are not compressed on the fly on any protocol: compressing
  reads the whole file for every request.

See [Conditional and range requests](https://github.com/aofusa/veil-proxy/blob/main/docs/guide/routing.md).

## Proxy

- **Response header rules** (`add_response_headers`, `remove_response_headers`) apply on every protocol and path:
  HTTP/2 and HTTP/3 proxying, `buffering = "full"`, h2c and HTTPS HTTP/2 upstreams, kTLS `splice`, files and
  `Respond`. Listing `Server` or `Alt-Svc` also removes the ones veil adds itself.
- **`Server`** has the same value on every protocol (`server_header_value`, default `veil`). HTTP/3 used to send
  `veil/http3`.
- **`Alt-Svc`** is added on every HTTP/1.1 and HTTP/2 path that lacked it.
- **Compression** applies to h2c upstream responses for HTTP/1.1 and HTTP/2 clients. HTTP/3 `buffering = "full"`
  responses that were compressed now carry `Content-Encoding` (before, clients got gzip bytes as plain text).
- **Server-Sent Events** (`text/event-stream`) are never compressed and are streamed as they arrive. Before, a
  compressing route held an event stream until it ended, so clients received nothing. HTTP/2 clients also get
  responses of unknown length (read until the upstream closes) streamed instead of buffered.
- **`buffering = "full"` on HTTP/2** now buffers the whole upstream response before sending it, as on HTTP/1.1 and
  HTTP/3. Before, HTTP/2 counted the route in the metrics but streamed the response.
- **Buffered response bodies are capped at 64 MiB.** A response with a known length above that is sent
  uncompressed; a response of unknown length that grows past it is answered with 502.
- **Truncated upstream responses** (closed before `Content-Length` or the last chunk) reset the HTTP/2 stream instead
  of ending it as if complete, as HTTP/3 already did.
- **Uploads cut off by the client.** When an HTTP/2 or HTTP/3 client resets a request in the middle of its body, the
  upstream now sees an incomplete request. Before, it received a complete chunked body and processed the partial
  data.
- **Circuit breaker and outlier detection** count results of HTTP/2 and HTTP/3 requests, not only HTTP/1.1.
- **`client_body_timeout_secs`** (default 30) applies to HTTP/2 and HTTP/3 request bodies:
  - HTTP/2 resets the stream with `RST_STREAM(CANCEL)`; HTTP/3 uses `H3_REQUEST_CANCELLED`.
  - `[http2] stream_idle_timeout_secs` (default 60) is now used for HTTP/2 streams without a route, including a
    client that stops in the middle of a header block (HEADERS without the CONTINUATION that ends it).

## Proxy-Wasm

- `on_http_response_headers` runs on every path: HTTP/2 to HTTP/1.1 upstreams, HTTP/1.1 to h2c upstreams, compressed
  responses and `buffering = "full"`.
- `proxy_send_local_response` header names are lowercased, and headers containing CR, LF or NUL are dropped
  (HTTP/2 and HTTP/3 clients rejected uppercase names). A status outside 100–599 becomes 500.
- `on_http_response_body` runs on HTTP/1.1 and HTTP/2, not only HTTP/3. Only routes with a module that has
  `allow_response_body_read` buffer the response; other routes keep streaming.

## Metrics

- Recorded on every protocol now:
  - `veil_grpc_requests_total` and `veil_grpc_stream_duration_seconds` (HTTP/2 and HTTP/3 gRPC relays)
  - `veil_proxy_buffering_used_total`
  - `veil_retry_total`
  - `veil_circuit_breaker_open_total`
  - `veil_proxy_cache_stores_total` (its `storage` label is where the entry is actually kept)
- `veil_circuit_breaker_state` is the state of the whole upstream group: 1 if any server is open, 2 if any is half
  open, otherwise 0. Before, it showed the state of the last server that served a request.
- `veil_outlier_ejected` returns to 0 when an ejection ends.

## Upgrade notes

- **Slow uploads over HTTP/2 and HTTP/3** are now cut off after `client_body_timeout_secs` (default 30) without
  body data, as HTTP/1.1 already was. Raise it on routes that receive slow streaming uploads.
- **`client_header_timeout_secs`** in `[route.security]` was never used: a route is known only after the headers
  arrive. It is still accepted, with a warning at start-up.
- **HTTP/3 `Server` header:** `veil/http3` is now `veil`, or your `server_header_value`.
- **WebSocket** is supported on HTTP/1.1 only. The guides now say so.
- **HTTP/1.1 file routes** with `[route.compression]` now compress. To keep sending these files uncompressed with
  `sendfile`, remove the compression section from those routes.

## Known limitations

- Prebuilt BSD binaries are x86_64 only (aarch64 BSD: build from the ports or from source).
- macOS binaries are not signed with a Developer ID or notarized. Homebrew and `cargo binstall` installs are not
  affected by Gatekeeper; an archive downloaded with a browser may need `xattr -d com.apple.quarantine veil`.
- A Proxy-Wasm callback that traps or exceeds its time limits lets the request continue (fail open) outside the
  mesh; see [Proxy-Wasm](https://github.com/aofusa/veil-proxy/blob/main/docs/guide/wasm.md#default-settings).
- Precompressed `.br`/`.gz` siblings of static files are not served.
- WebSocket over HTTP/2 and HTTP/3 (RFC 8441, RFC 9220) is not supported.
