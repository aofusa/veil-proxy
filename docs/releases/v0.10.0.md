# veil v0.10.0

veil 0.10.0 adds several listening ports in one process, the OS certificate store for outgoing TLS, static caches
that follow changes on disk, CORS on actual responses and Proxy-Wasm request bodies on every protocol. The API
library (Rust, Python, C) gains WebSockets, HTTP/1.1 upgrades, multipart uploads, response compression, an
offline Swagger UI, gRPC in OpenAPI, FastAPI compatibility for Python, and two helper packages:
`veil-proxy-kit` (Rust) and `veil-api-kit` (Python). These are the changes since 0.9.2.

## Install

| | |
|---|---|
| Debian, Ubuntu | signed apt repository, `apt install veil` (the service starts) |
| RHEL-compatible, Fedora, Amazon Linux | signed dnf repository, `dnf install veil`, `systemctl enable --now veil` |
| Homebrew (macOS, Linux) | `brew install aofusa/tap/veil`, `brew services start veil` |
| Windows | MSI and zip (x64 and arm64) on this page; `winget install Aofusa.Veil` |
| FreeBSD, OpenBSD, NetBSD | ports for each tree (`veil-0.10.0-bsd-ports.tar.gz`, [packaging/bsd/ports](https://github.com/aofusa/veil-proxy/blob/main/packaging/bsd/ports/README.md)) |
| Rust | `cargo binstall veil-proxy` (prebuilt, minisign-verified) or `cargo install veil-proxy --locked --features full` |
| Container | `ghcr.io/aofusa/veil` and `docker.io/aofusa/veil` (same digests and signatures) |
| Kubernetes | `helm install veil oci://ghcr.io/aofusa/charts/veil --version 0.10.0` |
| API library | Rust `veil-proxy` + `veil-proxy-kit` on crates.io; Python `veil-api` + `veil-api-kit` on PyPI; C headers and libraries in the release assets |

Where each one puts the configuration and how veil finds it:
[docs/guide/running.md#configuration-file](https://github.com/aofusa/veil-proxy/blob/main/docs/guide/running.md#configuration-file).

## New in the proxy

- **Several listening ports (`[[listener]]`).** Each listener has its own address, TLS on or off, HTTP/2 (ALPN),
  HTTP/3, plain HTTP/1.1 and h2c, an HTTPS redirect and its own worker threads. The existing `[server] listen` and
  `listen_cleartext` keep working and are treated as two implicit listeners, so existing configurations behave as
  before. See [docs/guide/configuration.md](https://github.com/aofusa/veil-proxy/blob/main/docs/guide/configuration.md).
- **The OS certificate store for outgoing TLS.** `tls_ca = "system"` (or `"builtin"`, a file, or a list) on a
  backend, and `[tls_client] ca` as the default for every outgoing connection. The store is read once at start-up,
  before the sandbox. The packaged default configurations use `"system"`; the container image and the Helm chart
  use `"builtin"`.
- **Static caches follow changes on disk.** `watch = true` on `[route.open_file_cache]` and
  `[route.static_file_cache]` (defaults `[performance] open_file_cache_watch` and `[static_file_cache] watch`)
  invalidates cached files through inotify, kqueue or ReadDirectoryChangesW. A cache hit costs one atomic read.
- **CORS on actual responses.** `[route.traffic.cors]` now adds its headers to every response of the route (file,
  proxy, handler, Wasm), not only to preflights. `override_upstream` and `reject_disallowed` control what happens
  when the upstream sets its own CORS headers or the origin is not allowed.
- **Proxy-Wasm.** The request-body phase works on HTTP/1.1 and HTTP/2 (before, only HTTP/3). `instance_reuse =
  true` keeps one VM context per request across phases (as Envoy does) instead of starting a fresh instance for
  every callback. A `Respond` route can answer from a module, and `data_files` exposes files read at start-up as
  `plugin_data.<name>`. Long callbacks yield to other requests of the same worker every
  `[wasm.defaults] yield_interval_us` (default 1000 µs).

## New in the API library

- **WebSockets** for Rust, Python and C (RFC 6455, permessage-deflate, Autobahn-tested), listed in OpenAPI. Idle
  WebSockets get a ping every 30 s and are closed after 120 s without a frame (`[api] websocket_*`).
- **HTTP/1.1 upgrades** (`Response::switching_protocols`, `Upgraded`) for custom protocols.
- **multipart/form-data uploads** with limits on parts, field size, file size and the whole body, spooling large
  files to temporary files (Rust `Multipart`, Python `Form()`/`File()`/`UploadFile`, C `VEIL_ROUTE_FORM`).
- **Response compression** for handler routes (`[route.compression]` or `[api] compression = true`; br and gzip
  chosen from `Accept-Encoding`).
- **Swagger UI bundled** with the library (`[api] openapi_docs_ui = "embedded"`), so `/docs` works without
  internet access; `"cdn"` and `"off"` remain available.
- **gRPC methods in OpenAPI** as `POST /pkg.Svc/Method` with proto3-JSON schemas (`[api] openapi_grpc`).
- **Python:** `async def` handlers and WebSockets run on persistent event loops (uvloop when installed);
  `Depends`, `Security`, `BackgroundTasks`, `APIRouter`, `dependency_overrides`, `response_model` and the other
  FastAPI route options; `veil.asgi.run(app)` and `app.mount()` run an ASGI app such as an existing FastAPI app.
- **Helper packages:** `veil-proxy-kit` (Rust: cookies, sessions, CORS, authentication, GraphQL, gRPC client,
  static files, dependency injection, background tasks) and `veil-api-kit` (the same for Python, pure Python).
- **A production guide** for the library: [docs/guide/library-production.md](https://github.com/aofusa/veil-proxy/blob/main/docs/guide/library-production.md).

## Security

These come from a review of the whole code base (sandbox, protocols, runtime, build and release).

- **The seccomp filter covers every thread.** It is installed with `SECCOMP_FILTER_FLAG_TSYNC`, so threads started
  before the workers (health checks, Proxy-Wasm tick and gRPC, reloads, VDS, ACME) are filtered too; start-up stops
  if a thread cannot be synchronized. Landlock is applied to every thread that does not read the configuration or
  certificates, and it now also restricts executing files and creating symbolic links, sockets, FIFOs and devices
  outside the allowed paths. The allow-list gains `dup`, `dup3`, `unlink(at)`, `mkdir(at)`, `rename(at)` and
  `chmod`, which UNIX-socket listeners, disk spill-over and ACME need (`docker/assets/security/seccomp*.json` too).
- **Pausing veil no longer breaks it under seccomp.** `restart_syscall` is allowed, so stopping and resuming the
  process (`docker pause`, `SIGSTOP`/`SIGCONT`, attaching a debugger) no longer kills the reload and health-check
  threads (in `strict` mode they disappeared silently and veil then ignored `SIGTERM`). This affected earlier
  versions too.
- **`seccomp_mode = "strict"` terminates the whole process,** as documented. It used to kill only the thread that
  made the disallowed call, leaving veil running without it.
- **HTTP/3 limits handshakes.** New `[http3]` keys: `max_connections` (default 10000), `retry_threshold` (default
  1000; above it, Initial packets without a token get a Retry, which proves the source address) and
  `handshake_timeout` (default 10000 ms). Spoofed Initial packets no longer create unlimited connections.
- **HTTP/3 memory (quiche advisories GHSA-4fgf-9xrr-88gf and GHSA-4q5x-gp38-rfp4, High):** the vendored quiche
  carries the upstream 0.29.3 fixes. A frame no longer reserves memory for the length it announces before the bytes
  arrive, header sections are limited by the new `[http3] max_field_section_size` (default 65536, advertised to
  clients; checked on the announced length and while QPACK decodes), and path events are consumed so a client that
  keeps changing its source port cannot grow a queue for the life of the connection.
- **HTTP/2 HPACK:** the encoder's dynamic table is capped at 4096 bytes whatever `SETTINGS_HEADER_TABLE_SIZE` a peer
  announces.
- **Control characters:** HTTP/2 and HTTP/3 reject field values with control characters other than HTAB (as HTTP/1.1
  does), and the text access log writes control characters from requests as `\xNN`.
- **Forwarded headers:** by default, `X-Forwarded-For`, `X-Real-IP`, `X-Forwarded-Proto` and `Forwarded` sent by
  clients are no longer passed to the upstream; `X-Forwarded-For` carries the client address instead. Senders listed
  in `[route.security] trusted_proxies` keep theirs (see the upgrade notes).
- **Admin API and metrics:** the admin secret is compared in constant time, failed authentications are limited to
  10 per minute per address, and an empty `allowed_ips` in `[admin]` and `[prometheus]` now allows only loopback.
- **JWT:** `[route.jwt] allowed_algs` fixes the accepted algorithms; a JWKS key without `alg` is logged as a warning
  at load time.
- **Proxy-Wasm host functions** no longer sign-extend guest pointers and lengths, so hostile values are rejected
  instead of wrapping.
- **Upstream responses with more than 64 headers** fail with 502 at once instead of waiting for more data.
- **Upstream HTTP/1.1 connections are reused only after the whole response was read.** If an upstream stopped a
  chunked response for longer than the read timeout, the half-read connection went back to the pool and the next
  request on it (possibly another client's) read the rest of the earlier response. Now the client connection is
  closed (HTTP/2 and HTTP/3 streams are reset) and the upstream connection is dropped. Bytes after the end of a
  response are not forwarded, and incomplete bodies are no longer cached or compressed as if complete.
- **Conflicting upstream framing** (`Transfer-Encoding` together with `Content-Length`, or several different
  `Content-Length` values) now fails with 502. `Transfer-Encoding` takes precedence over `Content-Length`, as
  RFC 9112 requires.
- **Mesh authorization (xDS RBAC):** rules veil cannot evaluate (`metadata` and `matcher` permissions) now fail
  closed in DENY policies too (before, such a DENY policy denied nothing), and a principal `url_path` matches the
  request path instead of everyone.
- **Logs:** invalid UDP datagrams are counted in `veil_http3_invalid_packets_total` instead of logged one by one at
  `warn`.
- **Runtime (io_uring and UDP):** buffers of in-flight receives and sends are no longer freed while the kernel still
  uses them on shutdown; control messages are read and written without alignment assumptions; a panic in a
  file-system offload job fails only that request; kTLS key material is zeroed after use.
- **Dependencies and build:** zstd 0.14 (RustSec advisories against 0.13); the vendored quiche carries the upstream
  fix for GHSA-mh64-ph39-mrc9 (C FFI only, which veil does not build); vendored crates are now checked against
  RustSec and GitHub advisories, including those published only on the upstream repository; GitHub Actions and Docker base images are pinned by digest and `rustup-init` is
  verified by checksum.

## Fixes

- **HEAD, 204 and 304 from an HTTP/1.1 upstream** with a `Content-Length` no longer wait 30 seconds for a body
  that never comes (HTTP/1.1 and HTTP/2 listeners; HTTP/3 already handled it).
- **Buffered routes (`[route.buffering]`)** answer 502 when the upstream body is incomplete and 507 when it is
  larger than the buffer limit; they used to send what had arrived (cut at `max_memory_buffer` when no disk buffer
  was set) under the original `Content-Length`. Close-delimited responses are read until the upstream closes.
- **Expect: 100-continue** is answered only after the route's checks pass, so a request over the route's body limit
  or `[api] max_body_size` gets 413 instead of 100 Continue and a reset connection.
- **Out of file descriptors:** when `accept` fails with EMFILE on macOS, Windows and the BSDs, the worker no longer
  spins; it pauses accepting for 100 ms and keeps serving its connections.
- **Upstream connections by host name** try every resolved address (for example IPv4 after `::1` for
  `localhost` on macOS).
- **HTTP/1.1 keep-alive:** a pipelined request that arrives right after a body is no longer lost on routes that read
  the body (Proxy-Wasm, handlers).
- **Proxy-Wasm:** shared data (`proxy_set_shared_data`) is shared by every request of a module and kept across
  reloads; filters no longer trap with "interrupt" under load on several workers; local responses to HEAD, 204 and
  304 carry no body; `proxy_dequeue_shared_queue` returns the message as the ABI defines it (a pointer to memory
  from the module's allocator), so shared queues work with the proxy-wasm SDKs; WASI `random_get` fills buffers from
  the operating system's cryptographic random source (it used a clock-seeded generator whose output was predictable).
- **Route cache:** a route with header or query conditions earlier in the list is no longer skipped.
- **Reloads:** turning HTTP/2 off is applied to ALPN; changes to listening addresses, threads, `[http3]` and `[[l4]]`
  are logged as a warning that a restart is needed instead of being ignored silently; a rejected reload leaves the static cache
  settings unchanged.
- **Performance:** request futures for HTTP/2 streams and static files are smaller (the Proxy-Wasm phases are boxed
  only when a route has modules), which lowers CPU per request for small HTTP/2 responses.
- **Static file watcher:** its thread runs inside the seccomp and Landlock sandbox, and on BSD and macOS it leaves
  enough descriptors for connections.

## Upgrade notes

- **Python `async def` handlers** now run on persistent event loops instead of the handler thread pool. Set
  `[api] python_async_mode = "pool"` to keep the 0.9 behavior.
- **New defaults in `[api]`:** WebSockets and upgraded connections time out when idle (`websocket_idle_timeout_secs
  = 120`, `websocket_ping_interval_secs = 30`, `upgrade_idle_timeout_secs = 300`); multipart bodies are limited as a
  whole (`multipart_max_total_size`).
- **`veil-proxy-kit` and `veil-api-kit` JWT** require an `exp` claim by default, and the Python kit always checks
  `aud`.
- **ASGI apps** see `scheme = "https"` for TLS connections; `X-Forwarded-Proto` is used only from trusted proxies (`forwarded_allow_ips`, default `127.0.0.1`, as in uvicorn).
- **Forwarded headers (proxy):** if veil runs behind a load balancer or CDN whose `X-Forwarded-For` the upstream
  relies on, list it in `[route.security] trusted_proxies`. `forwarded_headers = "passthrough"` restores the 0.9
  behavior. `X-Real-IP` is not added by default; add it with `add_request_headers = { "X-Real-IP" = "$client_ip" }`.
- **`[admin]` and `[prometheus]`:** with `allowed_ips` empty, only loopback can connect. List the addresses of your
  scrapers and tools if they connect over the network.
- **`[http3]`:** more than 10000 connections per listener, or a large number of handshakes at once, are refused or
  sent a Retry by default. Raise `max_connections` and `retry_threshold` for very large deployments.
- **seccomp and Landlock** now cover threads that were outside them. Custom seccomp profiles for the container must
  include the new syscalls and `restart_syscall` (the bundled ones do).
- **HTTP/2 and HTTP/3 requests** with control characters in header values are rejected.

## Known limitations

- Prebuilt BSD binaries are x86_64 only (aarch64 BSD: build from the ports or from source).
- macOS binaries are not signed with a Developer ID or notarized. Homebrew and `cargo binstall` installs are not
  affected by Gatekeeper; an archive downloaded with a browser may need `xattr -d com.apple.quarantine veil`.
- HTTP/1.1 file responses are not compressed (HTTP/2 and HTTP/3 are), and precompressed `.br`/`.gz` siblings are
  not served.
