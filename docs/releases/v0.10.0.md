# veil v0.10.0

veil 0.10.0 adds several listening ports in one process, the OS certificate store for outgoing TLS, static caches
that follow changes on disk, CORS on actual responses and Proxy-Wasm request bodies on every protocol. The API
library (Rust, Python, C) gains WebSockets, HTTP/1.1 upgrades, multipart uploads, response compression, an
offline Swagger UI, gRPC in OpenAPI, FastAPI compatibility for Python, and two helper packages:
`veil-proxy-kit` (Rust) and `veil-api-kit` (Python). These are the changes since 0.9.2.

## Install

| | |
|---|---|
| Debian, Ubuntu | signed apt repository, `apt install veil` (the service starts) |
| RHEL-compatible, Fedora, Amazon Linux | signed dnf repository, `dnf install veil`, `systemctl enable --now veil` |
| Homebrew (macOS, Linux) | `brew install aofusa/tap/veil`, `brew services start veil` |
| Windows | MSI and zip (x64 and arm64) on this page; `winget install Aofusa.Veil` |
| FreeBSD, OpenBSD, NetBSD | ports for each tree (`veil-0.10.0-bsd-ports.tar.gz`, [packaging/bsd/ports](https://github.com/aofusa/veil-proxy/blob/main/packaging/bsd/ports/README.md)) |
| Rust | `cargo binstall veil-proxy` (prebuilt, minisign-verified) or `cargo install veil-proxy --locked --features full` |
| Container | `ghcr.io/aofusa/veil` and `docker.io/aofusa/veil` (same digests and signatures) |
| Kubernetes | `helm install veil oci://ghcr.io/aofusa/charts/veil --version 0.10.0` |
| API library | Rust `veil-proxy` + `veil-proxy-kit` on crates.io; Python `veil-api` + `veil-api-kit` on PyPI; C headers and libraries in the release assets |

Where each one puts the configuration and how veil finds it:
[docs/guide/running.md#configuration-file](https://github.com/aofusa/veil-proxy/blob/main/docs/guide/running.md#configuration-file).

## New in the proxy

- **Several listening ports (`[[listener]]`).** Each listener has its own address, TLS on or off, HTTP/2 (ALPN),
  HTTP/3, plain HTTP/1.1 and h2c, an HTTPS redirect and its own worker threads. The existing `[server] listen` and
  `listen_cleartext` keep working and are treated as two implicit listeners, so existing configurations behave as
  before. See [docs/guide/configuration.md](https://github.com/aofusa/veil-proxy/blob/main/docs/guide/configuration.md).
- **The OS certificate store for outgoing TLS.** `tls_ca = "system"` (or `"builtin"`, a file, or a list) on a
  backend, and `[tls_client] ca` as the default for every outgoing connection. The store is read once at start-up,
  before the sandbox. The packaged default configurations use `"system"`; the container image and the Helm chart
  use `"builtin"`.
- **Static caches follow changes on disk.** `watch = true` on `[route.open_file_cache]` and
  `[route.static_file_cache]` (defaults `[performance] open_file_cache_watch` and `[static_file_cache] watch`)
  invalidates cached files through inotify, kqueue or ReadDirectoryChangesW. A cache hit costs one atomic read.
- **CORS on actual responses.** `[route.traffic.cors]` now adds its headers to every response of the route (file,
  proxy, handler, Wasm), not only to preflights. `override_upstream` and `reject_disallowed` control what happens
  when the upstream sets its own CORS headers or the origin is not allowed.
- **Proxy-Wasm.** The request-body phase works on HTTP/1.1 and HTTP/2 (before, only HTTP/3). `instance_reuse =
  true` keeps one VM context per request across phases (as Envoy does) instead of starting a fresh instance for
  every callback. A `Respond` route can answer from a module, and `data_files` exposes files read at start-up as
  `plugin_data.<name>`. Long callbacks yield to other requests of the same worker every
  `[wasm.defaults] yield_interval_us` (default 1000 µs).

## New in the API library

- **WebSockets** for Rust, Python and C (RFC 6455, permessage-deflate, Autobahn-tested), listed in OpenAPI. Idle
  WebSockets get a ping every 30 s and are closed after 120 s without a frame (`[api] websocket_*`).
- **HTTP/1.1 upgrades** (`Response::switching_protocols`, `Upgraded`) for custom protocols.
- **multipart/form-data uploads** with limits on parts, field size, file size and the whole body, spooling large
  files to temporary files (Rust `Multipart`, Python `Form()`/`File()`/`UploadFile`, C `VEIL_ROUTE_FORM`).
- **Response compression** for handler routes (`[route.compression]` or `[api] compression = true`; br and gzip
  chosen from `Accept-Encoding`).
- **Swagger UI bundled** with the library (`[api] openapi_docs_ui = "embedded"`), so `/docs` works without
  internet access; `"cdn"` and `"off"` remain available.
- **gRPC methods in OpenAPI** as `POST /pkg.Svc/Method` with proto3-JSON schemas (`[api] openapi_grpc`).
- **Python:** `async def` handlers and WebSockets run on persistent event loops (uvloop when installed);
  `Depends`, `Security`, `BackgroundTasks`, `APIRouter`, `dependency_overrides`, `response_model` and the other
  FastAPI route options; `veil.asgi.run(app)` and `app.mount()` run an ASGI app such as an existing FastAPI app.
- **Helper packages:** `veil-proxy-kit` (Rust: cookies, sessions, CORS, authentication, GraphQL, gRPC client,
  static files, dependency injection, background tasks) and `veil-api-kit` (the same for Python, pure Python).
- **A production guide** for the library: [docs/guide/library-production.md](https://github.com/aofusa/veil-proxy/blob/main/docs/guide/library-production.md).

## Fixes

- **Expect: 100-continue** is answered only after the route's checks pass, so a request over the route's body limit
  gets 413 instead of 100 Continue and a reset connection.
- **Out of file descriptors:** when `accept` fails with EMFILE on macOS, Windows and the BSDs, the worker no longer
  spins; it pauses accepting for 100 ms and keeps serving its connections.
- **Upstream connections by host name** try every resolved address (for example IPv4 after `::1` for
  `localhost` on macOS).
- **HTTP/1.1 keep-alive:** a pipelined request that arrives right after a body is no longer lost on routes that read
  the body (Proxy-Wasm, handlers).
- **Proxy-Wasm:** shared data (`proxy_set_shared_data`) is shared by every request of a module and kept across
  reloads; filters no longer trap with "interrupt" under load on several workers; local responses to HEAD, 204 and
  304 carry no body.
- **Route cache:** a route with header or query conditions earlier in the list is no longer skipped.
- **Reloads:** turning HTTP/2 off is applied to ALPN; changes to listening addresses, threads, `[http3]` and `[[l4]]`
  are logged as a warning that a restart is needed instead of being ignored silently; a rejected reload leaves the static cache
  settings unchanged.
- **Static file watcher:** its thread runs inside the seccomp and Landlock sandbox, and on BSD and macOS it leaves
  enough descriptors for connections.

## Upgrade notes

- **Python `async def` handlers** now run on persistent event loops instead of the handler thread pool. Set
  `[api] python_async_mode = "pool"` to keep the 0.9 behavior.
- **New defaults in `[api]`:** WebSockets and upgraded connections time out when idle (`websocket_idle_timeout_secs
  = 120`, `websocket_ping_interval_secs = 30`, `upgrade_idle_timeout_secs = 300`); multipart bodies are limited as a
  whole (`multipart_max_total_size`).
- **`veil-proxy-kit` and `veil-api-kit` JWT** require an `exp` claim by default, and the Python kit always checks
  `aud`.
- **ASGI apps** see `scheme = "https"` for TLS connections; `X-Forwarded-Proto` is used only from trusted proxies (`forwarded_allow_ips`, default `127.0.0.1`, as in uvicorn).
- No changes are needed in existing proxy configurations.

## Known limitations

- Prebuilt BSD binaries are x86_64 only (aarch64 BSD: build from the ports or from source).
- macOS binaries are not signed with a Developer ID or notarized. Homebrew and `cargo binstall` installs are not
  affected by Gatekeeper; an archive downloaded with a browser may need `xattr -d com.apple.quarantine veil`.
- HTTP/1.1 file responses are not compressed (HTTP/2 and HTTP/3 are), and precompressed `.br`/`.gz` siblings are
  not served.
