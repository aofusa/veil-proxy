# veil v0.9.2

veil 0.9.2 fixes the Windows binaries: they no longer need the Visual C++ runtime. veil itself has the same code
as 0.9.1; the other changes are in how releases are packaged and distributed.

## Install

| | |
|---|---|
| Debian, Ubuntu | signed apt repository, `apt install veil` (the service starts) |
| RHEL-compatible, Fedora, Amazon Linux | signed dnf repository, `dnf install veil`, `systemctl enable --now veil` |
| Homebrew (macOS, Linux) | `brew install aofusa/tap/veil`, `brew services start veil` |
| Windows | MSI and zip (x64 and arm64) on this page; `winget install Aofusa.Veil` once the package is accepted |
| FreeBSD, OpenBSD, NetBSD | ports for each tree (`veil-0.9.2-bsd-ports.tar.gz`, [packaging/bsd/ports](https://github.com/aofusa/veil-proxy/blob/main/packaging/bsd/ports/README.md)) |
| Rust | `cargo binstall veil-proxy` (prebuilt, minisign-verified) or `cargo install veil-proxy --locked --features full` |
| Container | `ghcr.io/aofusa/veil` and `docker.io/aofusa/veil` (same digests and signatures) |
| Kubernetes | `helm install veil oci://ghcr.io/aofusa/charts/veil --version 0.9.2` |

Where each one puts the configuration and how veil finds it:
[docs/guide/running.md#configuration-file](https://github.com/aofusa/veil-proxy/blob/main/docs/guide/running.md#configuration-file).

## Fixes

- **The Windows `veil.exe` did not start without the Visual C++ runtime (B-167).** The 0.9.0 and 0.9.1 Windows
  binaries (zip and MSI, x64 and arm64) were linked against `VCRUNTIME140.dll` and the Universal CRT DLLs, so on a
  Windows without the Visual C++ Redistributable they failed with "VCRUNTIME140.dll was not found"
  (exit code `0xC0000135`). The C runtime is now linked statically. Each release now checks that `veil.exe`
  imports no C runtime DLL and runs `veil.exe --version` in a Nano Server container, which has no Visual C++
  runtime.
- **OpenBSD port.** The `_veil` user and group now use id 906, the next free id in OpenBSD's `user.list`.

## Packaging and distribution

- **Homebrew.** The formula no longer repeats the version given by the URL (`brew audit --strict` rejected it), and
  the release test now runs `brew audit --strict` before publishing.
- **After publishing (release-downstream).** The minisign key secret may contain only the key line, the Docker Hub
  mirror copies the cosign signatures (OCI referrers) with the images, and re-running the workflow uses the
  scripts of the workflow's commit, so a failed step can be re-run after a fix. Updating the Homebrew tap no longer
  fails when only the tap's CI is missing.

## Upgrade notes

- No configuration or behavior changes from 0.9.1.
- **Windows:** if you installed the Visual C++ Redistributable only for veil, it is no longer needed.

## Known limitations

- Prebuilt BSD binaries are x86_64 only (aarch64 BSD: build from the ports or from source).
- macOS binaries are not signed with a Developer ID or notarized. Homebrew and `cargo binstall` installs are not
  affected by Gatekeeper; an archive downloaded with a browser may need `xattr -d com.apple.quarantine veil`.
- winget: the package `Aofusa.Veil` is under review in winget-pkgs; later versions are proposed automatically.
