# veil v0.9.0

veil is now installable from package managers, each of which installs a default configuration and page so that
veil answers on <http://127.0.0.1:8080/> right after installation: apt and dnf repositories, Homebrew, winget,
BSD ports, `cargo binstall`, a Docker Hub mirror and a Helm chart. Every GitHub release now carries the binaries,
packages, checksums and signatures for all platforms, built and tested in CI. This release also adds migration
guides from nginx and Envoy, a Grafana dashboard, and fixes three bugs found along the way.

## Install

| | |
|---|---|
| Debian, Ubuntu | signed apt repository, `apt install veil` (the service starts) |
| RHEL-compatible, Fedora, Amazon Linux | signed dnf repository, `dnf install veil`, `systemctl enable --now veil` |
| Homebrew (macOS, Linux) | `brew install aofusa/tap/veil`, `brew services start veil` |
| Windows | `winget install Aofusa.Veil` (MSI, x64 and arm64) |
| FreeBSD, OpenBSD, NetBSD | ports for each tree (`veil-0.9.0-bsd-ports.tar.gz`, [packaging/bsd/ports](https://github.com/aofusa/veil-proxy/blob/main/packaging/bsd/ports/README.md)) |
| Rust | `cargo binstall veil-proxy` (prebuilt, minisign-verified) or `cargo install veil-proxy --locked --features full` |
| Container | `ghcr.io/aofusa/veil` and now `docker.io/aofusa/veil` (same digests and signatures) |
| Kubernetes | `helm install veil oci://ghcr.io/aofusa/charts/veil --version 0.9.0` |

Where each one puts the configuration and how veil finds it:
[docs/guide/running.md#configuration-file](https://github.com/aofusa/veil-proxy/blob/main/docs/guide/running.md#configuration-file).

## Changes

- **Configuration file (F-247).** veil reads `-c FILE`, then the new `VEIL_CONFIG` environment variable, then the
  default path: `/etc/veil/config.toml`, and on Windows `%ProgramData%\veil\config.toml`. Source builds can set
  their own default path at build time (`VEIL_DEFAULT_CONFIG_PATH`, used by the BSD ports). veil has no built-in
  configuration: without a file it stops with an error that names the path it looked for. `--help` is in English
  and shows the default path.
- **Release archives (F-247).** The `.tar.gz` / `.zip` archives contain the binary, the licenses, a README and an
  example configuration and page in `examples/` (`./veil -c examples/config.toml`). They are built in CI for Linux
  (glibc 2.28 and musl, x86_64 and aarch64), macOS (universal2), Windows (x86_64, aarch64) and FreeBSD, OpenBSD and
  NetBSD (x86_64), and each one is started and checked on its platform before the release is drafted.
- **Signatures and provenance (F-247, F-249).** `SHA256SUMS` is signed with Sigstore (keyless, by this
  repository's release workflow), every asset has a GitHub build-provenance attestation, and the archives have
  minisign signatures that `cargo binstall` checks.
- **deb and rpm (F-251).** The default configuration is `/etc/veil/config.toml` (a conffile /
  `%config(noreplace)`, never overwritten), the page is `/usr/share/veil/www/`, and the default listens on
  `127.0.0.1:8080` (plaintext). The packages no longer generate a self-signed certificate and no longer depend on
  openssl. On Debian and Ubuntu the service is enabled and started on install; on RPM systems it is not (Fedora
  policy). Upgrading no longer disables the service.
- **Helm chart (F-254).** `oci://ghcr.io/aofusa/charts/veil` (cosign-signed): TLS from a Secret, HTTP/3 on a
  separate UDP Service, metrics with a ServiceMonitor, the Grafana dashboard as a ConfigMap, HPA, PDB and
  NetworkPolicy; non-root, read-only root filesystem, `RuntimeDefault` seccomp.
- **Docker Hub mirror (F-248).** `docker.io/aofusa/veil` has the same tags, digests and signatures as
  `ghcr.io/aofusa/veil`.
- **Migration guides (F-255).** [From nginx](https://github.com/aofusa/veil-proxy/blob/main/docs/guide/migration-nginx.md)
  and [from Envoy](https://github.com/aofusa/veil-proxy/blob/main/docs/guide/migration-envoy.md) (English and
  Japanese): concepts, directive tables including what veil does not have, examples, operations. Every complete
  example passes `veil -t` in CI, and representative examples are run side by side with nginx / Envoy and compared.
- **Grafana dashboard (F-256).** `examples/grafana/veil-overview.json` and a `docker compose` example with veil,
  Prometheus and Grafana. A test queries every panel, so a renamed metric is caught.

## Fixes

- **The proxy cache never stored small responses (B-162).** Responses whose body arrived with the headers were
  never cached, so for most small responses every request went to the backend. Note that the proxy cache applies
  to HTTP/1.1 clients only; HTTP/2 and HTTP/3 requests always go to the backend (now documented; F-257).
- **Static files under a relative `File` path returned 403 on HTTP/1.1 (B-160).** A route such as
  `path = "examples/www/"` answered 403 for every file over HTTP/1.1 on Linux (HTTP/2 worked).
- **A failed startup exited with status 0 (B-161).** Configuration or bind errors now exit with status 1, so
  systemd's `Restart=on-failure`, rc.d and scripts see the failure.

## Upgrade notes

- **deb / rpm users of 0.8.x** (configuration in `/var/etc/veil/config.toml`): the package keeps using that file
  (it writes `VEIL_CONFIG=/var/etc/veil/config.toml` to `/etc/default/veil` or `/etc/sysconfig/veil`). To move to
  `/etc/veil/config.toml`, copy your settings there, delete that line and restart veil. The self-signed
  certificate the 0.8.x package created in `/var/etc/veil/ssl/` is left as it was.
- **Windows:** `veil` without `-c` now reads `%ProgramData%\veil\config.toml` (it used to look for
  `/etc/veil/config.toml`).
- **Scripts that start veil** and relied on exit status 0 after a startup error now get 1.
- **Route paths:** a `path` without `*` is an exact match (`"/"` matches every path); use `"/api/*"` for a prefix.
  This was already the behavior; the migration guides now say it explicitly.

## Known limitations

- Prebuilt BSD binaries are x86_64 only (aarch64 BSD: build from the ports or from source).
- macOS binaries are not signed with a Developer ID or notarized. Homebrew and `cargo binstall` installs are not
  affected by Gatekeeper; an archive downloaded with a browser may need `xattr -d com.apple.quarantine veil`.
- winget: the first version is submitted to winget-pkgs by hand; later versions are proposed automatically.
