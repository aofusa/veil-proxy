veil quickstart

You are looking at the default page installed with veil. It is served by the default configuration over plaintext HTTP/1.1 and HTTP/2 (h2c) on port 8080, and every request is logged. Here is where things are, how to serve your own files and configuration, and where to read more.

1. Where things are

veil reads the configuration file given with -c FILE, otherwise the one in VEIL_CONFIG, otherwise the default path. Packages put a default configuration and this page there.

Binary only (release archive, cargo install, cargo binstall) No file is installed: create the configuration and the page yourself and pass the file with -c (the release archive has an example: ./veil -c examples/config.toml).

Outside the container, the default configuration listens on 127.0.0.1:8080 only, so nothing is exposed to the network until you change it. Check a configuration with veil -t and reload it without downtime with SIGHUP (for example systemctl reload veil).

2. Container image

docker run --rm -p 8080:8080 ghcr.io/aofusa/veil
# open http://localhost:8080/   (h2c works too: curl --http2-prior-knowledge http://localhost:8080/)

No certificate is needed. Every request is logged to standard output, so docker logs shows it.

Tags: latest / musl (static binary on scratch), glibc (glibc on Wolfi), and versioned tags such as musl-v0.9.2. All are multi-arch (amd64, arm64).

Serve your own HTML

Mount a directory over /var/www. index.html is served for /.

mkdir -p site && echo '<h1>Hello from veil</h1>' > site/index.html
docker run --rm -p 8080:8080 -v "$PWD/site:/var/www:ro" ghcr.io/aofusa/veil

Use your own config.toml

The configuration file is /etc/veil/conf.d/config.toml. Mount yours over it.

docker run --rm -p 8080:8080 \
  -v "$PWD/config.toml:/etc/veil/conf.d/config.toml:ro" \
  -v "$PWD/site:/var/www:ro" \
  ghcr.io/aofusa/veil

# check a configuration without starting the server
docker run --rm -v "$PWD/config.toml:/etc/veil/conf.d/config.toml:ro" \
  ghcr.io/aofusa/veil /veil -t -c /etc/veil/conf.d/config.toml

3. Edit the configuration

The default configuration in its minimal form (the container listens on 0.0.0.0, the other installs on 127.0.0.1; replace /var/www/ with the page directory of your install):

[server]
listen_cleartext = "0.0.0.0:8080"   # plaintext HTTP/1.1 + h2c
enable_secure_redirect = false      # no TLS listener, so do not redirect to https

[access_log]
enabled = true                      # one line per request on stdout

[[route]]
[route.conditions]
path = "/"
[route.action]
type = "File"
path = "/var/www/"

Reverse proxy to another service

[[route]]                           # put this route before the "/" route
[route.conditions]
path = "/api/"
[route.action]
type = "Proxy"
url = "http://backend:3000"

Routes are evaluated in the order they are written and the first match wins, so put /api/ above the / route: /api/ goes to the backend and everything else is served from /var/www. In a container, put both containers on the same Docker network so that backend resolves.

TLS and HTTP/3

[server]
listen = "0.0.0.0:443"              # TLS (HTTP/1.1 and HTTP/2 via ALPN)
listen_cleartext = "0.0.0.0:8080"

[tls]
cert_path = "/etc/veil/ssl/cert.pem"
key_path = "/etc/veil/ssl/key.pem"

[http3]
enabled = true
listen = "0.0.0.0:443"
docker run --rm -p 8080:8080 -p 443:443/tcp -p 443:443/udp \
  -v "$PWD/config.toml:/etc/veil/conf.d/config.toml:ro" \
  -v "$PWD/ssl:/etc/veil/ssl:ro" -v "$PWD/site:/var/www:ro" \
  ghcr.io/aofusa/veil

4. Good to know

  • The container image works under Docker's default seccomp profile and Kubernetes RuntimeDefault (it uses the epoll backend, not io_uring).
  • In the container, veil starts as root, binds its listeners, then drops to the nonroot user, with its own seccomp filter and Landlock. Paths you mount must be readable by uid/gid 65532. Paths outside the default Landlock list need to be added to [security] landlock_read_paths.
  • Reload the configuration without downtime: docker kill -s HUP <container>.
