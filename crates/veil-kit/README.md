# veil-kit

Helpers for the API server library of [veil](https://github.com/aofusa/veil-proxy) (`veil::api`): cookies, redirects,
static files, CORS, authentication (Basic, API keys, JWT), sessions, HTTP and gRPC clients, GraphQL, dependency
injection and background tasks. The crate is separate from veil: the proxy binary and veil's default features do not
include it, and the heavy dependencies (async-graphql, prost) are behind features.

```toml
[dependencies]
veil = { package = "veil-proxy", version = "0.9", default-features = false, features = ["full", "api"] }
veil-kit = { package = "veil-proxy-kit", version = "0.9", features = ["full"] }
```

```rust,no_run
use std::time::Duration;
use veil::prelude::*;
use veil_kit::auth::jwt::{Claims, Jwt, JwtKey, JwtVerifier};
use veil_kit::cookie::{Cookie, CookieJar, ResponseCookieExt};
use veil_kit::cors::Cors;
use veil_kit::tasks::{BackgroundTasks, Tasks};

#[veil::route(path = "/api/me", method = "GET")]
async fn me(token: Jwt<Claims>, jar: CookieJar, tasks: BackgroundTasks) -> Response {
    let theme = jar.get("theme").map(|t| t.into_owned()).unwrap_or_else(|| "light".into());
    tasks.add(async move { /* runs after the response was sent */ });
    Response::text(format!("{} {}", token.0.sub.as_deref().unwrap_or("-"), theme))
        .with_cookie(Cookie::new("seen", "1").http_only(true))
}

fn main() -> Result<(), veil::api::Error> {
    App::new()
        .state(JwtVerifier::new([JwtKey::hs256(b"0123456789abcdef0123456789abcdef")]))
        .with(Cors::new().allow_origins(["https://app.example.com"]).on("/api"))
        .with(Tasks::new().every(Duration::from_secs(60), || async { /* periodic work */ }))
        .with(veil_kit::serve::dir("/assets", "./public"))
        .run()
}
```

| Module | Feature | Contents |
|---|---|---|
| `cookie` | `cookie` (default) | `CookieJar`, `Cookie` (RFC 6265bis checks), `SignedCookieJar` (HMAC-SHA256), `PrivateCookieJar` (AES-256-GCM), `Key` with rotation |
| `redirect` | always | `Redirect` (301/302/303/307/308), `Redirect::safe` against open redirects |
| `serve` | always | `serve::dir` (veil's file server: sendfile, Range, ETag, caches), `serve::file` |
| `cors` | `cors` (default) | CORS middleware with automatic preflight answers |
| `auth` | `auth` (default), `jwt` | `BasicAuth`, `BearerToken`, `ApiKey`, `Jwt<Claims>` (HS, RS, PS, ES256/384, EdDSA, JWKS), `Principal`, `Auth`, `authenticate`, `require`, `OAuth2PasswordBearer` |
| `session` | `session` | encrypted cookie sessions or a server store (`SessionStore`, `MemoryStore`) |
| `client` | always | `veil::api::client` (HTTP/1.1, h2, h2c, Unix sockets, mTLS) plus `get_json`, `post_json`, `retry` |
| `grpc` | `grpc` | `ProstCodec`, `connect`, `Balanced` (round robin, failover); clients are generated by `veil-build` |
| `graphql` | `graphql`, `graphiql` | async-graphql 7 over HTTP, SSE and WebSocket (`graphql-transport-ws`, `graphql-ws`) |
| `di` | `di` (default) | `Container` (singleton, scoped, transient), `Dep<T>`, replacement at run time |
| `tasks` | `tasks` (default), `cron` | `BackgroundTasks` after the response, `Tasks::spawn`, `every`, `cron` |

Cryptography uses the provider crate of veil's TLS (aws-lc-rs, or ring on OpenBSD and NetBSD); there is no
`jsonwebtoken`, `cookie` or `tower` dependency.

Guide: [docs/guide/library-kit.md](https://github.com/aofusa/veil-proxy/blob/main/docs/guide/library-kit.md).
Examples: [`examples/api/rust-kit`](https://github.com/aofusa/veil-proxy/tree/main/examples/api/rust-kit) and, with
tower-http instead of this crate,
[`examples/api/rust-tower-recipes`](https://github.com/aofusa/veil-proxy/tree/main/examples/api/rust-tower-recipes).
